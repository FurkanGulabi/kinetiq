# M1 hardware session: FluidNC connection (2026-11-08)

**Setup:** ESP32-WROOM-32U running FluidNC over USB-C. The USB-serial bridge is a CH340 (VID 0x1A86, PID 0x7523), which appears as `/dev/tty.usbserial-110` (`crw-rw-rw-`). No motion commands were sent.
**Kinetiq:** dev server, CNCjs log level `silly` (logs every serial line), connected through the Kinetiq UI at 115200 baud.

## Notes

- The controller is in **Alarm** at connect. With `$22=1` (homing enabled), FluidNC expects `$H` or `$X` before motion. Nothing was sent.
- FluidNC is running its WiFi access point (`SSID=FluidNC`, `192.168.0.1`). Kinetiq does not use it, but it is an open entry point to the controller unless secured in the FluidNC config.

Clicked in the Kinetiq UI; replies captured through the backend. No motion command was sent (Home was **not** pressed).

```
15:50:14.390 STATE Hold:0
15:50:30.217 WRITE "~"        (Resume)
15:50:30.686 STATE Idle
```

- **Reset does not clear the boot alarm** (homing enabled, `$22=1`). Home (`$H`) or Unlock (`$X`) is required.
- A soft reset makes FluidNC print its banner, so after a Reset Kinetiq picks up the identity even without `$I`.
- FluidNC enters `Hold:0` on `!` even when idle; `~` returns it to Idle.
- The machine was left **Idle (unlocked, not homed)**.

## Coordinates & Jog widget (same day)

- Readouts in the UI match the status reports: work X 0.000 / Y 0.000 / Z −22.603, machine 0.000 / 0.000 / 0.000 (WPos = MPos − WCO). Units `mm` (`$13=0`), WCS `G54`.
